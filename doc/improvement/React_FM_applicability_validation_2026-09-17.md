**2026-09-17｜v2 已完成，11 个起点，四组×两次重复**

## 当前结论

**已修复“把开关证据绑定到电机”的具体检查器错误，但没有得到条件检查优于直接观察的可靠证据。暂不扩大付费实验，也不把这轮结果写成历史记忆的能力增益。**

条件检查组三步内修复 **13/22**，先观察组 **12/22**，差 **+4.5 个百分点**；按 episode 配对重采样的描述性 95% 区间为 **[−13.6, +27.3] 个百分点**。六步内分别为 15/22、14/22。区间很宽，不能证明优势，也不能证明等效。

更关键的是：5 个历史命中起点、共 10 次检查，**没有一次历史被接受并传入修复器**。本轮检验的是拒绝不匹配历史与选择观察的效果，不能据此证明正确历史能提供额外知识。一个看似有利的电机案例中，三组的修复请求逐字相同，后续成功差异来自相同输入下的生成和执行波动。

本次恢复后的探针与 v2 实验约 **¥2.60**；连同本轮采集和 v1 中断尝试，本轮合计 **¥5.11 / ¥20**。全程累计台账 **¥35.87 / ¥100**，另保留 ¥10 覆盖早期未完整记账的连通性测试。费用是 token 台账的保守估计，不是服务商实际账单。运行进程已正常退出，没有遗留付费任务。

## 1. 实际做了什么

模型固定为 `deepseek-ai/DeepSeek-V4-Flash`，temperature=0、关闭 thinking。经验库与检索结果均冻结，未写入新经验，也未按本轮结果调整检索。

从六个原任务族的官方 dev 划分，固定选择第 3–5 个 variation，共 18 个 episode。每个最多采集 40 个 actor 回合，取第一次显式、非终止失败；预先排除精确的“门没有打开”错误。11 个 episode 产生了合格起点，来自 5 个任务族；另外 7 个中，4 个到达回合上限，2 个终止为 −100，1 个终止为 100。没有补选替换，也没有按检索命中筛选。

这些是开发数据。v1 中断前已经看过部分结果，并据此修正了检查器；v2 复用全部 11 个冻结起点，属于**开发回归，不是独立确认**。原 v1 的 23 条分支没有混入 v2 比较。

| 组别 | 干预方式 |
|---|---|
| 即时修复 direct | 一次修复调用，只读当前状态与轨迹 |
| 先观察 observe | 准备调用选择至多一次查看／阅读，再由独立修复调用处理；不读历史 |
| 原始历史 memory | 一次修复调用，附加冻结的自动检索历史 |
| 条件检查 checked | 准备调用检查历史；已有观察支持且无需补充观察时才接受，否则拒绝历史，可选择一次观察，再由独立修复调用处理 |

准备理由不会传入修复器；只传实际观察，以及获准使用的原始历史。若先观察，本次不再重新批准历史。这是保守的一次前置检查，不是多轮条件推理系统。observe 与 checked 的调用层级相同，但选择的观察动作可能不同。

主要指标在运行前固定为**前三个总环境动作内完成原失败的局部修复**，额外观察也占动作预算。每分支上限为六个环境动作、18 个 actor 回合、¥0.10。六步修复、受阻动作和得分只是补充指标。

最终完成 **88/88 条逻辑分支**，即每组 22 条；其中 **64 条实际执行、24 条共享引用**。六个未命中历史的起点中，memory 共享 direct，checked 共享 observe，避免把相同策略的随机差异当成记忆效果；费用只计算实际调用。统计单位为 11 个 episode，不是 88 个独立样本。

预定主要比较是 checked−observe：全体为 +4.5 个百分点，区间 [−13.6, +27.3]。只看 5 个命中起点，三步修复分别为 **5/10 与 4/10**，差 +10.0 个百分点，区间 **[−30.0, +60.0]**。命中子集样本尤其少。

平均任务得分增量依次为 +7.18、+7.64、−0.86、+4.36，没有分支达到 100 分。条件检查的局部修复计数略高，却没有更高的得分增量；短程修复不能替代完整任务表现。

## 3. 哪些机制判断已有直接证据

### 对象约束确实拦住了已知错误

v1 在 `power-component__12__26` 中，用 inventory 里 **switch 的 anode/cathode 描述**，批准了当前 **electric motor** 接线失败所检索的历史。修复器因此把目标误诊为开关。

v2 针对这一真实故障增加约束：接线历史若要获准，引用必须支持当前连接目标的端子，不能仅证明别的对象有相似端子。新实验两次重复均再次出现同类错误批准，程序均以 `connection_target_not_supported_by_quote` 拦截。真实电机证据的离线正例仍可接受，相关 9 项测试通过。

这证明补丁覆盖了已观察到的故障。它只约束当前接线目标，不是所有对象、操作和物理前提的通用验证器。

### “多修好一个”不足以归因于记忆

在 `power-component__13__24` 的两次重复中，direct、observe、checked 发给独立修复器的 **system 与 user 消息逐字相同**：observe 没有选择额外观察，checked 拒绝历史且也没有额外观察。准备理由未泄漏。

checked 两次均在第三个动作前完成接线，而 direct 均未完成；但是 checked 的修复建议仍使用错误的 `electric motor terminal 1`。它成功是因为 actor 后续自行 `look at electric motor`，读到真实端子名后改用 `anode`。不能把这个差异写成历史提供了正确知识，或检查器生成了更好的诊断。

### 本轮主要暴露的是历史覆盖问题

冻结检索的五个命中分别是：电机错误检索到两条开关接线经验、定位电机检索到电池断线经验、拾取肥皂检索到橙子／碗经验、打开高炉检索到房间导航经验。它们都有对象或操作不匹配，未形成干净的“当前状态不足、历史能补足”的支持性案例。

checked 在 10 次命中检查中接受 0 次，选择额外观察 1 次；observe 在全体 22 次中选择观察 7 次。拒绝理由本身仍可能不准确，不能当作事实标注。下一步的关键未知是经验库是否真的包含可转移的额外信息，而不是怎样把拒绝率调得更高。

## 4. 质量检查与限制

- **675 次实际调用全部完成**，本次没有 API 错误或未结算请求；所有模型标识正确。
- 11 个起点均跑齐四组×两次；共享分支逐字段一致，且没有额外调用；冻结输入、局部判定和运行代码保持不变。
- 准备与修复请求的输入约定已核验；拒绝历史后不向修复器传入历史文本或准备理由。所有分支均遵守费用与动作上限。
- 实际分支中 60 条达到六步上限、3 条提前终止、1 条预算停止。预算停止发生在第五个动作后，保留为策略在给定预算下的结果，没有补跑。
- 19 次 actor 输出、4 次修复输出达到预设 token 上限；准备调用没有此类截断。本轮未临时放宽限制，结果只适用于这套输出预算。
- `power-component__14__0` 的已知可执行修复路径需要五步，三步指标自然不利，因此同时报告六步指标。种植消歧只确认目标类型的 cherry seed 被聚焦，不声称重放后隐藏对象身份完全一致。
- 样本小、仅一个模型，且已用于开发；没有证明完整 episode 成功率、跨任务泛化或包含建库成本的全生命周期优势。

## 5. 下一步计划与 AAMAS 判断

**当前不进入扩大样本或继续调检查器的付费阶段。** 同一批起点上的额外重复不能解决“没有可用历史知识”和“已用于开发”的问题。

建议下一阶段先完成一个不需要模型 API 的证据检查：

1. 在冻结的 533 条训练经验中，核查是否存在真实可迁移的规则；分别记录当前观察能否直接给出答案、历史是否确实补充信息，以及目标对象和前提是否一致。没有支持性案例，就停止把通用失败记忆作为主贡献继续优化。
2. 若能找到支持性案例，再预先固定未用于改检查器的评估起点，同时包含适用、不适用、信息不足三类。保留先观察基线，在相同费用和动作限制下对照；先确定样本和主要指标，再看结果。
3. 只有独立起点上出现可复核的历史增量，才继续完整 episode 与更多任务验证。若只能减少坏记忆干扰，论文主张应限于适用性诊断或可靠使用条件，不能称能力提升。

就现有证据而言，**尚未形成支持 AAMAS 方法优势的实证链条**。可保留的资产是冻结经验库、预算约束下的配对评估、具体对象错绑反例与可复算日志；下一步是否值得发展为论文，取决于能否找到并独立验证历史的不可替代信息。
