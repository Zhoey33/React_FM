# 历史纠错记忆与即时纠错：等预算研究

日期：2026-09-16。状态：文献、历史数据核查与两轮新实验均已完成；所有统计保留原始环境分。

## 研究问题与当前判断

研究对象是失败发生后，使用之前任务中提炼的修复经验，是否比根据当前任务状态现场生成修复建议更值得花钱。不是比较“有记忆的完整系统”与一个预算更少、模型更弱的基线。

目前没有证据支持“历史记忆在相同预算下普遍更好”。它可能在重复出现、稳定、需要环境特定知识的错误上有优势；当错误从当前反馈就能推理出来，或者经验不适用于当前状态，直接纠错可能更好。这些适用条件仍是需要进一步独立验证的研究假设；本轮两次配对比较均未建立稳定优势。

必须区分两种成本问题：

1. **部署成本**：已经有记忆库，从同一失败状态出发，给每组相同的剩余预算。
2. **全生命周期成本**：把获得历史轨迹、提炼经验、索引、后续更新也算上，再看整个任务流的效果与成本。

本轮先测第一种，并明确报告第二种的建设成本敏感性。不能把部署阶段优势自动写成从零开始等预算优势。

两轮都已完成，模型统一为 `deepseek-ai/DeepSeek-V4-Flash`。v2、v3 是本地实验协议的版本号，不是模型版本。每分支共同 API 预算上限为 ¥0.12；实际使用略低于上限，原因是下一次调用前必须预留费用。

### 机制、敏感性与成本

- 9 个关门阻挡起点中，初测的无干预组在 18/18 条分支里都于五个环境动作内进入原目标房间，平均只需两步。复测的记忆与现场组也各为 18/18、两步。此类简单前提错误没有显示必须依赖历史经验；后续终局分差不能直接算作原错误的修复增益。
- 剔除两个无法凭描述唯一对齐种子的起点后，初测记忆 − 现场为 +2.594 分，区间 [-9.694, 14.813]，仍不足以判定稳定优势。
- 初测同一方法两次重复的绝对分差，记忆平均 17.278、现场平均 14.833 分。复测中则分别为 1.923、14.923 分。任务和实现条件会影响波动，不能用一个好例子替代配对统计。
- 初测仅一条现场分支达到 100 分，复测没有达到 100 分的分支。本轮主要说明有限预算内的局部任务推进，不能支撑完整任务成功率的强主张。
- 两轮正式运行分别为 ¥15.923583、¥5.395842，合计 **¥21.319425**（按日间公开价、不扣缓存优惠的估算上界）。两轮共 6,570 次已取得 usage 的调用，没有未结算预约或不明响应。独立行为预检另约 ¥0.109，初始连通性测试由预检余量覆盖；整体仍在 ¥100 授权范围内。

**当前建议：不把“历史记忆在等预算下优于现场纠错”作为 AAMAS 的已成立主张。** 先完善共同 actor 的接口操作，再用同一个现场修复器“带/不带冻结历史信息”作增量信息对照，并在独立测试集与多个预算点验证。这样可以区分历史知识的价值、提示形式的作用、额外推理的作用和接口缺陷。本轮不继续为了得到显著结果追加样本。

(2026-06)](https://arxiv.org/html/2606.15017v1) | WebArena 的三个模型设置中，增加普通 actor 步数的基线在聚合成功率上追平或超过 AWM、ASI、ReasoningBank；计入模块开销与膨胀的 actor 输入，并报告三次运行波动。 | 其预算控制是步数近似匹配，作者承认不是逐任务严格上限；基线还有规则式页面裁剪。没有直接比较 ScienceWorld 同一失败状态的即时纠错与历史修复，不能当作所有记忆无效的定理。 |

文献检索不是穷尽式系统综述。上述结论来自论文原文，而不是二手宣传。当前可信缺口是**历史经验的适用条件、额外信息价值与预算机会成本**，不能把增加检测/检索/gate 模块直接视为新颖性。

### 旧主实验不能回答等预算问题

111 个 ScienceWorld episode：ReAct 42 次成功、原始均分 47.2072；React-FM Online 46 次成功、原始均分 55.2432。后者旧报告的 64.25 截断了负分。两次运行配对后，16 个由失败变成功、12 个由成功变失败，且无多次独立重复；这不是因果救回/破坏计数。

| 干预 | 分支数 | 平均最终分增量 | 最终分上涨分支 | 达到 100 分的分支 |

## 新的配对 pilot

用户授权实际 API 开销最多 ¥100，并指定 `deepseek-ai/DeepSeek-V4-Flash`。当前实验执行器是 `experiments/compare_memory_direct.py`。

### 控制条件

- 六类任务：boil、melt、power-component、test-conductivity、grow-plant、chemistry-mix；每类前两个官方 dev variation，共采集 12 个独立 episode，得到 18 个 checkpoint；其中一个 episode 没有出现入选的显式错误。
- 以无记忆 actor 收集最多 40 回合；每个 episode 取最先出现的最多两种显式错误，各一个 checkpoint。**不根据任何分支的效果或记忆命中来挑样本**。重复等待不直接视为失败。
- 每个 checkpoint 四组、各两次重复；随机打乱执行组顺序。相同 actor、初始观察、最近 10 回合、当前 room/inventory。
- 每组从 reset + 完整 action prefix 重放开始；逐步核对 observation 和 score，并核对最终 room/inventory。ScienceWorld 会重排物体列表及歧义选项编号：只对已识别的无序列表做规范化，歧义选项按完整物体描述对应后重放选择；对象、容器关系、得分等实质差异仍导致 checkpoint 全组排除并保存原因。18 个采集起点均已通过两次离线回放。这是可观察状态一致性检查，不是隐藏状态逐位相等的证明。两个 grow-plant 起点有五个描述完全相同的 cherry seed，无法用描述唯一对齐具体种子；主分析保留原定样本，并额外报告剔除这两个起点的敏感性结果。该标记在这两个起点分支运行之前由输入轨迹确定。
- 共用规则：不得连续输出 think。首次连通性/代理行为预检独立保存在 `results/20260916_memory_vs_direct`；正式配对为 `results/20260916_memory_vs_direct_v2`。

### 四组定义

| 组 | 第一个后续 actor 回合收到的信息 | 额外费用 |
|---|---|---|
| continue | 当前任务、历史和状态 | actor 调用 |
| cue | 上述信息 + 明确失败提醒 | 提醒增加的输入 |
| direct | 上述信息 + 同模型基于同一状态生成的修复建议 | 修复调用和建议增加的输入，均计入组预算 |
| memory | 上述信息 + 训练库中检索出的 top-1 经验；无命中时保留失败提醒和固定适用性提示 | 本地检索时间、记忆增加的输入；不调用即时修复兜底 |

主对比为 memory − direct，cue 用于区分“提醒了失败”和“提供了历史信息”。干预只注入第一回合，之后都靠相同 actor 继续；本轮测的是局部干预价值，不是部署全系统的最终任务成功率。记忆文本最多 1,400 字符、直接修复生成上限 192 tokens，两者格式不完全相同，长度带来的真实输入费用计入预算；因此结果首先评价这两个实际策略，不能把差异全部归因于历史信息本身。无命中组仍有固定适用性提示，也不与 cue 的提示文本完全相同。

冻结训练库：`memory_store/20260416_163135/sw_epoch1.json`，通过 `buckets` 加载实际为 533 条（文件的 `task_types` 是兼容副本，不能重复计数）。已从原始日志定向提取 214 条 episode 元数据，逐条核对其 variation 均属于官方 train，533 条记忆的 env_idx 和任务类型均映射到这些来源；与本轮官方 dev 不相交（见结果目录的 `memory_provenance_audit.json`）。混合 BM25/embedding 召回五条，沿用现有确定性筛选；旧条目缺少 failure_type 时仅从其既有错误观察用规则推断。不新增记忆、不用 dev 轨迹更新训练库。类型推断只用于检索结果的副本，正向/逆向查询的结果一致；冻结库在 18 个起点中有 13 个通过筛选，5 个无命中，后续分别报告命中/未命中描述性结果。

### 检索内容核查（不据分支效果挑选）

现有筛选并不保证“命中”等于“经验正确适用”：`melt__14__15` 的当前失败是 `open freezer door`，选中的经验却来自 `go to bathroom`，建议经相邻房间绕行。二者共享解析失败文本，但修复原因不同。这是实际检索策略的错配，后续结果不能泛化为高质量历史知识也无效。

另外两个起点更有可能体现环境规则迁移：`chemistry-mix__16__8` 检索到“把材料放进容器后执行 mix bowl”，`chemistry-mix__17__6` 检索到“读配方时省略 recipe titled”。这些只是依据内容提出的机制假设，最终仍须结合动作、观察和配对得分验证。`test-conductivity__450__31` 的历史建议允许把物品直接放在房间里，与当前要求放入指定盒子的目标存在冲突，也应逐步核查。

### 已完成起点的机制核查

`melt__14__15` 的两次 memory 最终分为 3、70，direct 为 3、3。但四条轨迹都在第一个实际环境动作正确执行了 `open freezer`。现场建议两次都准确指出应去掉 `door`；历史条目则是上节所述无关的导航经验。高分 memory 分支直到后续第 18 个 actor 回合执行 `focus on ice cream in glass cup` 才从 3 升到 70。

因此，“最终分多 33.5”不等于“历史知识更好地修复了开门错误”。它包含之后的探索、目标选择和执行波动。该例同时说明为什么既需要配对终局分，也需要检查原失败是否真的被纠正，且不能只挑高分成功故事。该例不决定总体结论，完整比较见前面的结果表。

## 补充复测：修复信息对称性与建议保留

v2 的实际日志暴露了一个对照问题：现场修复调用的 system 提示未包含 actor 的动作说明表，模型因此声称 mix 不是可用动作。另一个问题是 v2 建议只在首个 actor 回合出现，如果该回合输出 think，建议在首次实际动作前就消失。两者限制了对“历史信息价值”的解释，不能隐去后直接下结论。

为此保留全部 v2 原始结果，新增 `results/20260916_memory_vs_direct_v3` 复测：

- 使用原先 18 个起点中**13 个事先检索命中**的起点，选择依据是冻结检索结果，不是任何分支得分。共 13 × 2 组 × 2 重复 = 52 条分支。
- direct 与 memory 均采用原 actor、模型、状态、每分支 ¥0.12 上限和最多 60 actor 回合。
- 现场建议调用补齐 actor 的完整基础接口说明；两组建议均保留到首个实际环境动作完成，期间重复输入费用照常计入预算。
- v3 单独台账上限 ¥8；理论最大分支费用 ¥6.24，不重新采集起点。与 v2 的最多 ¥17.28 分支费用、已完成的 ¥0.964185 采集及预检预留合计仍低于 ¥100。
- 复测是看到 v2 的方法问题后做的修订，不伪装成独立预注册确认性实验。它回答“已有可检索经验时，两种完善后的策略如何比较”，不能直接替代覆盖所有失败点的部署效果。

建议跨 think 保留、修复调用获得接口说明的行为已用模拟调用检查。基础提示、actor 能力、冻结库质量与样本规模等限制依然存在。两轮均仅使用用户指定的一个模型，以及记忆库已覆盖任务家族中的 dev 变体；这不构成跨模型或全新任务类型的泛化证据。

## 共同 actor 的能力边界

本轮沿用 `prompts/scienceworld_prompts.py` 的基础提示与 few-shot，仅统一禁止连续 think。提示列出了动词，但没有完整动作语法或“歧义菜单只输出数字”的接口规则。实际分支多次把选项写成 `pick up glass cup 1`，环境返回 Unknown action。因而本轮结论仅适用于这个共同 actor；不能把它的接口操作问题一概视为复杂推理能力不足。

如果后续要把某类语法纠错收益写成论文贡献，应增加一个固定、任务无关的接口说明基线，检验同样的信息是否直接写进基础提示就足够。历史记忆若只是补齐稳定 API 语法，其收益还不是历史经验特有的信息价值。本轮没有事后修改共同 actor 或据此替换样本。

## 全生命周期：记忆要用多少次才能回本

若质量可比，设建设费用为 C_build，每个后续任务的平均实际成本分别为 c_memory、c_direct，则只有 c_direct > c_memory 时，成本回本任务数才可写作：

`N_break_even = C_build / (c_direct - c_memory)`。

若 memory 的单次运行反而更贵，增加使用次数不会自动回本。若两者质量不同，应报告效果—成本曲线，不应只比较成功数/token 比值。

训练库对应旧收集实验有 214 个 episode、41,928,483 tokens，其中 extractor 为 784,387 tokens。应分别报告：

- 已经因正常业务发生、可复用的历史轨迹：额外建设成本主要为抽取与索引。
- 专门为方法收集轨迹：轨迹采集也必须计入。

旧文件缺少足够的输入/输出账单拆分，本轮不能捏造其历史人民币支出。新 pilot 的冻结库部署比较也不会抹掉这些历史成本。

## AAMAS 决策如何受结果影响

1. 如果 memory 在 equal-cap 下不能稳定超过 direct/cue，不能继续使用“历史记忆优于直接纠错”作为核心主张。
2. 如果只在可重复的环境特定规则上有优势，而简单前提错误或新状态中没有优势，应以适用条件和错误干预为研究重点，并在新的任务上验证。
3. 如果只在忽略建设成本时有优势，主张必须限定为已有经验库、重复部署，并提供回本曲线。
4. 即使 pilot 有优势，也还需要扩大独立 episode、全程策略评估和研究差异核查；本轮不把小样本正结果视为投稿就绪。

## 后续完善：同一修复器的历史信息增量（运行前方案）
