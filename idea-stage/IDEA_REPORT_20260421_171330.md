# Idea Discovery Report

**Direction**: Reposition React_FM on ScienceWorld beyond ReAct / Reflexion by fusing recent validated ideas instead of pushing the learned gate line.
**Date**: 2026-04-21
**Pipeline**: scoped idea-discovery pass using local repo evidence + literature survey + novelty/risk screening + proposal refinement

## Executive Summary

Your current diagnosis is basically correct: on your own protocol, online React_FM is better than ReAct and Reflexion, but the margin is small, and the learned gate line is not the cleanest way to win. The recent ScienceWorld landscape suggests the benchmark has moved forward mainly through three mechanisms: better interface alignment, stronger causal/task abstractions in memory, and stronger exploration/planning policies.

The recommended next idea is **Interface-Aligned Causal Memory (IACM)**: keep your React_FM infrastructure, drop the learned gate as the headline contribution, and fuse two proven ideas instead: `ALIGN`-style agent-environment alignment and `CLIN`-style causal memory abstractions. Add a lightweight plan buffer only if the first fusion works. This is a cleaner story, cheaper to implement than RL/world-model papers, and better matched to your existing codebase.

## Literature Landscape

### 1. What your local evidence already says

- On your current Step 4 ScienceWorld protocol, the strongest no-gate setting is **online React_FM ExpA** at **41.44% success** and **64.25 average raw score**.
- Corrected Reflexion improves over its own first pass, but still trails ExpA by **4.50 points** on success rate.
- The bottleneck is **not retrieval coverage**. Your runbook already shows offline memory B gets **100% retrieval hit**, but still does not beat ExpA.
- The task pattern is heterogeneous:
  - Memory helps: `grow-plant`, `chemistry-mix`, `melt`, `use-thermometer`
  - Online memory helps more than offline: `power-component`, `mendelian-genetics-known-plant`
  - Baseline still wins: `boil`, `inclined-plane-friction-unnamed-surfaces`, `test-conductivity`, `test-conductivity-of-unknown-substances`
- That means the main problem is now **memory usefulness and actionability**, not “can the system fetch a memory”.

### 2. External methods that matter

| Method | Venue / year | Main idea | ScienceWorld signal | Why it matters for you |
|---|---|---|---|---|
| SwiftSage | project page / 2023 | fast/slow reasoning, self-guided planning | reports **84.7 avg score** on full ScienceWorld | shows planning/state tracking matters more than naive retry |
| CLIN | COLM 2024 | extract **causal abstractions** from trajectories | reports **+23 absolute points** over Reflexion in same-task repeated interactions and **+21 points** in transfer | strongest evidence that raw verbal memory should be upgraded into reusable causal schemas |
| ALIGN | arXiv 2025 | automated agent-environment interface alignment | reports ReAct on ScienceWorld improving **20.03 -> 32.32**, a **+12.29** absolute gain | strong evidence that many failures are interface mismatch, not missing memory |
| EMPO2 | ICLR 2026 submission | online RL for long-horizon agentic tasks | reports ScienceWorld **75.9**, vs **33.2** for GRPO, **33.8** for Retrospex, **17.1** for Reflexion | shows exploration policy can dominate pure prompt-memory methods, but this route is expensive |
| NeSyS | arXiv 2026 | neuro-symbolic world modeling | reports world-modeling accuracy on ScienceWorld up to **88.0** average | not a direct policy baseline, but strong evidence that explicit state structure is useful |

### 3. Apples-to-apples warning

- These numbers are **not all directly comparable** to your local `41.44%` result.
- Your local number is a **12-core-task no-gate success rate**.
- SwiftSage and some newer papers report **average score** on the **official 30-task benchmark**.
- EMPO2 is an **RL-trained policy**, not a lightweight memory method.
- ALIGN focuses on **interface mediation**, so its gains tell you where the friction is, even if the exact metric setup differs.

The right reading is not “you are already below SOTA by X points”; it is:

- ReAct / Reflexion are no longer the right frontier anchors.
- The promising low-cost frontier for your setup is **interface + abstraction + light planning**, not another generation of gate tuning.

## Ranked Ideas

### 1. Interface-Aligned Causal Memory — RECOMMENDED

**One-line thesis**: Replace raw failure-recovery memories with task-conditioned causal/precondition memories, and only surface them through an interface-aligned prompt that exposes valid action forms, object roles, and hidden preconditions.

**Fusion source**:
- `ALIGN`: many ScienceWorld failures are action-interface mismatch
- `CLIN`: memory should encode causal abstractions, not just a verbatim fix
- React_FM: your existing retrieval, failure detection, and extractor pipeline

**Why this is the best fit**
- It attacks exactly the pattern your own data shows:
  - retrieval hits are already high
  - some tasks fail because the fix is not actionable in the current local state
  - some tasks fail because the model misunderstands the environment command grammar or preconditions
- It reuses the parts of your codebase that already work:
  - `src/scienceworld_memory_extractor.py`
  - `prompts/scienceworld_prompts.py`
  - `src/scienceworld_env.py`
- It gives a cleaner paper story than gate:
  - “memory is only useful when aligned to the environment interface and abstracted to causal preconditions”

**Minimal method sketch**
- Add an `interface adapter` before prompting:
  - compact action templates by task family
  - stable object-role hints
  - precondition reminders derived from environment/action context
- Rewrite each memory into structured fields:
  - `failure_trigger`
  - `missing_precondition`
  - `causal_rule`
  - `repair_template`
  - `negative_constraint`
- Inject memory only when the current failure matches the trigger/precondition pattern.
- Start with a deterministic selector or tiny heuristic. Do **not** lead with a learned gate.

**Expected win zone**
- `power-component`
- `test-conductivity`
- `test-conductivity-of-unknown-substances`
- `chemistry-mix`
- `mendelian-genetics-known-plant`

**Closest prior work**
- CLIN is the closest memory-side prior.
- ALIGN is the closest interface-side prior.

**Differentiation**
- Neither paper is “React_FM + interface alignment + causalized failure memory” as a lightweight retrofit for text-interactive agents.
- The novelty is moderate, not maximal. The paper would need strong ablations and task-level diagnosis.

**Status**: RECOMMENDED

### 2. Plan-State Memory with SwiftSage-lite Buffer — BACKUP

**One-line thesis**: Keep your current memory store, but add a short explicit plan buffer so memory is consumed relative to the current subgoal rather than the full history.

**Fusion source**:
- `SwiftSage`: fast/slow planning
- React_FM: retrieved repair traces

**Why it may work**
- Your current prompt is history-heavy and action-local.
- Some ScienceWorld failures are not “forgot a fix”; they are “lost track of experiment phase”.

**Risk**
- Easier to overbuild.
- If the plan buffer is not grounded in action validity, it becomes another verbose prompt trick.

**Status**: BACKUP

### 3. Branch-Distilled Explorer Policy — HIGH UPSIDE, HIGH COST

**One-line thesis**: repurpose your existing branched-rollout infrastructure, not to train a gate, but to distill better local action policies on the hard tasks.

**Fusion source**:
- `EMPO2` / `SPARK` style exploration-aware learning
- your current checkpoint / rollout stack

**Why it may work**
- It directly targets the limitation shown by newer RL papers: prompt memory alone does not learn exploratory behavior well enough.

**Why it is not the right next step**
- Too expensive and too far from the current paper narrative.
- It changes the project identity from “memory intervention” to “policy learning”.

**Status**: HOLD

## Eliminated Ideas

### A. Learned Gate as the main paper

- Your own results already suggest the gate line is fragile.
- The story is defensive rather than forward-moving.
- Even if it works, it risks looking like a narrow routing patch on top of older baselines.

### B. Pure retrieval upgrade

- Local evidence already says retrieval hit rate is not the core problem.
- Better retrieval alone is unlikely to solve actionability or precondition mismatch.

### C. Full world model / RL pivot right now

- Likely stronger ceiling, but mismatched to your current code, budget, and timeline.
- Too much implementation risk relative to the immediate gain.

## Deep Novelty Check

### Recommended idea: Interface-Aligned Causal Memory

**Closest papers**
- CLIN: causal abstractions in memory for agents
- ALIGN: better interfaces between agent and environment
- SwiftSage: structured planning for ScienceWorld

**Why this is still worth doing**
- The fusion is not an obvious copy-paste:
  - CLIN is about better memory abstraction
  - ALIGN is about interface mediation
  - your system already has failure-triggered memory insertion and benchmark-specific infrastructure
- The publishable version is not “we combined three things”.
- The publishable claim is:
  - raw memory underperforms because it is both **semantically under-abstracted** and **environmentally misaligned**
  - once rewritten into causal preconditions and surfaced through aligned interface hints, the same memory infrastructure becomes materially more useful

**Novelty risk**
- Moderate. This is more of a strong systems/benchmark paper than a pure conceptual novelty paper.
- To survive review, you need:
  - clean ablations
  - per-task diagnosis
  - at least one hard-task cluster where the gain is substantial and interpretable

## External Reviewer-Style Assessment

**What a strong reviewer will like**
- You are no longer comparing mainly to old baselines.
- The fusion is motivated by concrete benchmark pathology, not generic “memory helps” claims.
- The method is lightweight and falsifiable.

**What a reviewer will attack**
- “Why not just use a stronger planner or RL?”
- “Is this really more than prompt engineering?”
- “Are ALIGN-style hints leaking environment affordances unfairly?”
- “Is the gain only on a small subset of tasks?”

**Minimum answer you need**
- show that the interface adapter uses only information already available from the environment API or prompt context
- show that causalized memories beat verbatim memories at the same retrieval budget
- show that the method helps precisely where baseline memory is currently unstable
